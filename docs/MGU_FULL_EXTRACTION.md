# Full MGU extraction: lists first, assets on demand

The workflow is split into two stages. Stage 1 retrieves the x_call SDK and system information and creates a resource path index. Stage 2 downloads the indexed resource files only when requested.

## GUI

Run on macOS:

~~~sh
python3 scripts/mgu_diagnostics_gui.py
~~~

1. Press **Find MGU**, or enter **root@MGU-IP** manually.
2. Optionally enter an SSH identity file, for example **~/.ssh/mgu_root_key**.
3. Press **Get lists · SDK + system + asset index**. This retrieves x_call, reconstructs the SDK locally, saves SOME/IP/system inventory and scans resource paths. It does not download indexed assets.
4. After the list stage succeeds, press **Download assets**. This uses that exact index and downloads the files while preserving their paths.
5. Use **Open full extract** to inspect the timestamped output directory.

The GUI runs operations in background threads. Download assets remains disabled until a successful list stage has produced an index.

## Terminal

### Stage 1 — get lists

~~~sh
chmod +x scripts/extract-mgu-full.sh
MGU_SSH_KEY=~/.ssh/mgu_root_key ./scripts/extract-mgu-full.sh --lists root@192.168.1.50
~~~

If the key is already available through ssh-agent or ~/.ssh/config, omit MGU_SSH_KEY. The command prints an OUTPUT_DIR=... line; use that exact directory for stage 2.

### Stage 2 — download assets

~~~sh
MGU_SSH_KEY=~/.ssh/mgu_root_key ./scripts/extract-mgu-full.sh --download-assets root@192.168.1.50 "$HOME/BMW_MGU_Extract/YYYYMMDD-HHMMSS"
~~~

Stage 2 does not scan the MGU again. It reads assets/file_index.txt from the selected output directory and streams those exact paths from the MGU. It can be repeated if a transfer is interrupted.

Requirements: macOS OpenSSH (ssh/scp), tar, Node.js for stage 1, root SSH access, and enough free disk space for the selected assets.

## Stage 1 contents

- Downloads the preinstalled x_call@*.tgz archive and extracts it locally.
- Reconstructs oap-sdk/index.js, package.json and source/ from x_call/javascript/app.js using the vendored MIT-licensed [extract_sdk.js](../scripts/extract_sdk.js). This runs locally on the Mac, not on the MGU.
- Downloads /etc/oap/someip/someip-interfaces.json when readable.
- Saves OS/kernel, storage, preinstalled OAP app and /etc/oap inventories.
- Creates assets/file_index.txt by finding .png, .svg, .ttf, .otf, .json, .dds, .ktx and .bin files up to depth 6 under /usr/share, /usr/lib, /opt, /var/opt/public and /etc/oap.
- Does not download resource files.

## Stage 2 contents

- Reads only absolute paths listed in assets/file_index.txt.
- Streams a compressed tar archive over SSH directly to the Mac; no temporary asset archive is created on the MGU.
- Extracts files under assets/rootfs/, preserving their paths below the MGU root (for example rootfs/usr/share/...).
- Writes assets/download-report.txt when complete.
- Does not perform a new resource scan.

The index is generated by the MGU's find command. If a listed file is removed or becomes unreadable before stage 2, transfer may fail; rerun Get lists to refresh it. No hard size cap is imposed, so inspect the list and ensure adequate disk space before downloading.

## Output layout

~~~text
~/BMW_MGU_Extract/YYYYMMDD-HHMMSS/
├── README.txt
├── sdk/
│   ├── x_call@<version>.tgz
│   ├── x_call/
│   └── oap-sdk/
├── system_info/
│   ├── os-release-and-kernel.txt
│   ├── inventory.txt
│   └── someip-interfaces.json
└── assets/
    ├── file_index.txt
    ├── download-report.txt       (after stage 2)
    └── rootfs/
        ├── usr/share/...
        ├── usr/lib/...
        ├── opt/...
        ├── var/opt/public/...
        └── etc/oap/...
~~~

Every Get lists run creates a new timestamped directory, preserving earlier captures. The GUI's Download assets action targets the directory produced by its latest successful Get lists run.

## Safety and limitations

- Both stages are read-only on the MGU. No packages are installed, no firmware is flashed, no ECUs are coded, no services are restarted, and no MGU configuration is changed.
- Stage 2 transfers selected resources to the Mac; no temporary archive is written on the MGU.
- The number and total size of indexed files depends on installed MGU software and has not been measured on a real head unit. Download may use substantial network bandwidth, Mac disk space and MGU CPU time.
- Requires root SSH access and a compatible preinstalled x_call@*.tgz archive.
- Output may contain BMW proprietary SDK code, vehicle-platform configuration and resource assets. Keep it private and do not redistribute without permission.
- The scripts have not yet been run against a real MGU in this repository change.
